# JalNiti Data Dictionary (corrected, v2)

Synced with repository commit `a722a3a` (16 Oct 2026). `number` is a JavaScript number, `?` marks an optional field, `[]` marks an array.
Types are TypeScript interfaces: data shapes, not database tables. The app has no database server (see Architecture.md).

## 1. Ward and road model

| Entity | Field | Type | Meaning | Source |
|---|---|---|---|---|
| `StreetSegment` | `id` | `string` | Segment identifier, `S` plus 2 to 5 digits (`S01` to `S337` in the pilot ward) | Generated by the pipeline |
| `StreetSegment` | `name` | `string` | Road name | OpenStreetMap |
| `StreetSegment` | `osm_id` | `number` | OSM way identifier | OpenStreetMap |
| `StreetSegment` | `path` | `LatLon[]` | Road polyline | OpenStreetMap |
| `StreetSegment` | `length_m` | `number` | Length in metres | Calculated from the path |
| `StreetSegment` | `elevation_m` | `number` | Mean elevation of the segment's 3 sample points | SRTM via OpenTopoData (GMTED2010 fallback) |
| `StreetSegment` | `slope_pct` | `number` | Elevation drop across the sample points divided by length, in percent | DEM samples |
| `StreetSegment` | `dist_to_water_m` | `number` | Distance to the nearest mapped waterway or water body | OpenStreetMap + calculation |
| `StreetSegment` | `road_density` | `number` | Road density in the local neighbourhood | OpenStreetMap + calculation |
| `StreetSegment` | `base_risk` | `number` | Baseline waterlogging risk, 0.05 to 0.97. Weighted sum of four terms, each normalised across the ward: `0.34*(1-water) + 0.28*(1-slope) + 0.22*(1-elevation) + 0.16*road_density`. Water distance is capped at 1500 m and slope at 4 percent | Feature scoring |
| `StreetSegment` | `highway` | `string` | OSM road class | OpenStreetMap |
| `Depot` | `id`, `name` | `string` | Depot identifier and name. Pilot depots: D1 Navrangpura AMC Ward Office (4 trucks), D2 Ashram Road depot (3), D3 Gujarat University depot (3) | **Simulated assumption** |
| `Depot` | `lat`, `lon` | `number` | Depot coordinates | Configured |
| `Depot` | `trucks` | `number` | Number of simulated trucks at the depot. Truck objects are created inside `allocate()` from this count | **Simulated assumption** |
| `RainPoint` | `hour` | `string` | Hour of the reading | Open-Meteo |
| `RainPoint` | `mm` | `number` | Rainfall in mm for that hour. Model-estimated, not rain-gauge data | Open-Meteo |
| `NowcastPoint` | `time` | `string` | Time of a short-range forecast step | Open-Meteo |
| `NowcastPoint` | `mm` | `number` | Forecast rainfall in mm for that step | Open-Meteo |
| `WardData` | `segments` | `StreetSegment[]` | Street segments of the ward (337 in the pilot snapshot, at most 420) | Pipeline |
| `WardData` | `depots` | `Depot[]` | Simulated depots | Configured |
| `WardData` | `rainSeries` | `RainPoint[]` | Hourly rainfall history | Open-Meteo |
| `WardData` | `forecastMm`, `observedMm` | `number` | Forecast (next 24 h) and observed (last 24 h) rainfall totals in mm | Open-Meteo |
| `WardData` | `travelMin` | `number[][]` | Travel-time matrix in minutes (depots first, then segments). **Only the 3 depots and the 60 highest base-risk streets have measured OSRM values.** Every other pair holds `1000000000`, meaning "unreachable / not measured". No speeds are assumed | OSRM |
| `WardData` | `fetchedAt` | `string` | Time this response was assembled | Application |
| `WardData` | `geometryCapturedAt` | `string?` | Capture time of the replayed snapshot, if the snapshot was used | Snapshot |
| `WardData` | `notes` | `string[]` | Provenance and fallback messages | Pipeline |

## 2. Risk and scenario model

| Entity | Field / function | Type | Meaning |
|---|---|---|---|
| `ScenarioOverrides` | `rainMm` | `number` | Scenario rainfall in mm per 24 h, range 0 to 600. In live mode the dashboard sets it from observed rainfall plus the next 60 minutes. The 24 h forecast is shown but not used |
| `ScenarioOverrides` | `drainsCleared` | `string[]` | Segment IDs given the assumed de-silting benefit (risk multiplied by 0.7). At most 1000 |
| `ScenarioOverrides` | `closed` | `string[]` | Segment IDs **excluded from pumping targets**. This does not yet change the drawn routes. At most 1000 |
| `ScenarioOverrides` | `trucksAvailable` | `number` | Whole number of trucks, 0 to 50 |
| `ScenarioOverrides` | `shiftMinutes` | `number` | Planning shift in minutes, 30 to 720 (default 240) |
| `ScoredSegment` | `risk` | `number` | Risk score 0.01 to 0.99: `base_risk * log(1 + rainMm) / log(1 + 65)` |
| `ScoredSegment` | `band` | `RiskBand` | Category from the score (see Controlled values) |
| `ScoredSegment` | `exposure` | `number` | Optimizer weight: `risk * road_density * (length_m / 100) * 12`, rounded |
| `ScoredSegment` | `matrixIndex` | `number` | Position of the segment in `travelMin` (depot count plus index) |
| `ScoredSegment` | `mid` | `LatLon` | Segment midpoint |
| `ScoredSegment` | `confidence` | `Confidence` | `measured` if `slope_pct > 0` and `dist_to_water_m < 1500`, otherwise `indicative` |
| `defaultScenario(ward)` | function | `ScenarioOverrides` | Default scenario controls |
| `scoreSegments(ward, overrides)` | function | `ScoredSegment[]` | Applies rainfall and drain overrides, sorted by risk, highest first |
| `allocate(ward, scored, overrides)` | function | `AllocationResult` | Deterministic deployment plan |

## 5. Controlled values

| Type | Values and rule |
|---|---|
| `RiskBand` | `low` (risk below 0.35), `moderate` (0.35 and above), `high` (0.55 and above), `critical` (0.75 and above) |
| `Confidence` | `measured`, `indicative` |
| `AccessStatus` | `cut-off`, `at-risk`, `watch`, `clear`, `unknown` |

## 6. Constants

| Constant | Value |
|---|---|
| Reference rainfall (`reference_rain_mm`) | 65 mm per 24 h |
| Drain-clearing risk multiplier | 0.7 |
| Maximum segments built | 420 (337 in the snapshot) |
| Streets with exact travel times (`PLANNING_SEGMENTS`) | 60 |
| Local-search rounds | at most 12 |
| Cache lifetimes | ward 45 min, rainfall 2 min, hospitals 24 h |
| Live ward build budget | 35 s, then snapshot replay |
| Route request limit | 20 pairs |
